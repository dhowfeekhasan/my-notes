## TIL: FAISS Index Selection Guide

FAISS indexes trade off search speed, memory usage, and recall accuracy. **Flat indexes** (`IndexFlatL2`, `IndexFlatIP`) perform exhaustive search—guaranteeing 100% recall but scaling linearly ($O(N)$). Use these for datasets under ~1M vectors or when exact results are non-negotiable. **IVF (Inverted File)** indexes (`IndexIVFFlat`, `IndexIVFPQ`) cluster vectors into `nlist` centroids, searching only `nprobe` clusters at query time. This yields sub-linear speed ($O(\sqrt{N})$) with tunable recall; ideal for 1M–100M vectors where 95%+ recall is acceptable. **HNSW** (`IndexHNSWFlat`) builds a navigable proximity graph, offering the best speed/recall balance for high-dimensional data but consumes significant RAM (graph edges + vectors). Use for low-latency production serving when memory permits. **PQ (Product Quantization)** variants (`IndexPQ`, `IndexIVFPQ`) compress vectors into compact codes, enabling billion-scale indices on limited RAM at the cost of reconstruction accuracy.

Choose: **Flat** for prototypes/small data; **IVF+PQ** for large-scale offline batch search; **HNSW** for real-time serving with headroom; **PQ-only** for extreme compression on massive static datasets.

```python
import faiss
import numpy as np

# 1M vectors, 128-dim
d, nb = 128, 1_000_000
xb = np.random.random((nb, d)).astype('float32')

# IVF+PQ: 4096 centroids, 16 subquantizers (8 bits each)
nlist, m = 4096, 16
quantizer = faiss.IndexFlatL2(d)
index = faiss.IndexIVFPQ(quantizer, d, nlist, m, 8)

index.train(xb)  # Required for IVF/PQ
index.add(xb)
index.nprobe = 32  # Search 32 clusters at query time

# Search
xq = np.random.random((10, d)).astype('float32')
D, I = index.search(xq, k=5)
print(f"Top-5 indices shape: {I.shape}")
```
