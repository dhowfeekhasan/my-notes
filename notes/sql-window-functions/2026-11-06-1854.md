# TIL: SQL Window Functions Compute Over Related Rows Without Collapsing Them

Unlike `GROUP BY` aggregates, window functions (`OVER`) calculate a value for *each* row using a defined "window" of related rows. The result set retains the original row count, allowing you to mix detail (e.g., `salary`) with context (e.g., `AVG(salary) OVER (...)`) in a single query.

The `OVER` clause defines the window via three optional components: `PARTITION BY` (groups rows, like `GROUP BY` but keeps rows), `ORDER BY` (orders rows within the partition, required for ranking/running totals), and `ROWS/RANGE BETWEEN` (frames a physical subset, e.g., "3 preceding rows"). Functions fall into aggregates (`SUM`, `AVG`), ranking (`ROW_NUMBER`, `RANK`, `DENSE_RANK`), and navigation (`LAG`, `LEAD`, `FIRST_VALUE`).

**Crucial execution order:** Window functions run *after* `WHERE`, `GROUP BY`, and `HAVING`, but *before* `SELECT` output and final `ORDER BY`. You cannot reference a window function alias in the same query's `WHERE` clause; wrap it in a CTE or subquery to filter on the result (e.g., `WHERE rn = 1`).

```sql
WITH ranked AS (
  SELECT
    employee_id,
    department,
    salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
  FROM employees
)
SELECT * FROM ranked WHERE rn = 1; -- Top earner per department
```
